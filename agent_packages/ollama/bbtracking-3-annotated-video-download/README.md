# Package 3: Annotated Video Download

## Goal

Let the service expose the annotated video generated by analysis, and let the prototype display or download it after analysis completes.

## Current Context

- `track_video` writes an annotated `.avi`.
- `/analyze` currently returns JSON only.
- Prototype can import and play local videos but does not receive annotated output from the service.

## Target Files

Likely files:

- `service.py`
- `tests/test_service.py`
- `docs/service.md`
- `prototypes/mobile/index.html`
- `TODO.md`

## Required Behavior

Service:

- Add a way to retrieve annotated video for an analysis result.
- If async jobs exist, expose `GET /jobs/{job_id}/video`.
- If async jobs do not exist yet, add a minimal response field or endpoint design that does not break `/analyze`.
- Return a file response with `video/x-msvideo` or a reasonable content type.
- Keep temp file lifetime clear. For in-memory/local spike, files can live for the process lifetime or job lifetime.

Prototype:

- After completed service analysis, if a video URL is available, set the video player to the annotated video URL.
- Keep local imported video behavior.
- Provide status text when annotated video is unavailable.

## Constraints

- Do not base64 embed large videos in JSON.
- Do not commit generated videos.
- Avoid production storage complexity.
- Keep synchronous `/analyze` usable.

## Verification

Run:

```bash
/tmp/bbtracking-venv/bin/python -m pytest -q
git diff --check
```

Service smoke should verify that a known analysis can return a video response with non-zero body length.

## M3 Prompt

Use this package as the implementation brief. Produce exact patches. Prefer an endpoint returning `FileResponse` over embedding video bytes. If Package 2 async jobs is not implemented yet, design this as a small synchronous-compatible spike without breaking future async jobs.
